# Public real-robot matched re-execution feasibility audit

Audit date: 2026-08-09. Purpose: determine whether an existing public dataset
can replace new hardware collection for the paper's matched physical cell.

## Admission criteria

A public source qualifies only if its released evidence establishes all of the
following for each comparison:

1. the measured robot and target decision state is reset or matched;
2. the candidate action is actually executed from that state;
3. the compared executions differ in the earlier ordered history while current
   state, final-two suffix, unordered history, and candidate action satisfy the
   declared matching contract;
4. candidate-specific outcomes can be recomputed from physical observations;
5. run identifiers, timestamps, actions, observations, and reset provenance
   are available for an independent audit.

Approximate visual similarity, repeated task names, offline negative synthesis,
or successful/failed trajectories drawn from different episodes do not qualify.

## Sources checked

| Source | Relevant released evidence | Blocking mismatch | Decision |
|---|---|---|---|
| [Real Robot Challenge 2020](https://people.tuebingen.mpg.de/mpi-is-software/data/rrc2020/) | Per-run real TriFinger actions, robot/camera observations, goals, rewards, object trajectories, timestamps, and calibrations | Runs are separate participant/evaluation episodes; the release does not identify matched early-history pairs with the same committed candidate action from the same reset state | Reject for this claim |
| [Real Robot Challenge 2022](https://webdav.tuebingen.mpg.de/real-robot-challenge/2022/docs/tasks.html) | Real-robot offline datasets and remote policy evaluations for push/lift tasks, with observations, actions, goals, and rewards | Expert trajectories and policy evaluations do not provide the required same-action, different-history matched re-execution groups | Reject for this claim |
| [REASSEMBLE](https://tuwien-asl.github.io/REASSEMBLE_page/) | 4,551 real contact-rich trials with successes/failures and synchronized multimodal observations; four policy actions were each evaluated ten times | Board and object poses were intentionally randomized across demonstrations; repeated action names therefore do not establish a matched decision state or candidate | Reject for this claim |
| [Oopsie Data](https://oopsie-data.com/) | Real successful, suboptimal, and failed policy rollouts, including examples collected under similar conditions | “Similar conditions” are not an exact state/history/action contract, and public matched reset provenance is not established | Reject for this claim |
| [IMBench](https://imbench.org/) and its [released LeRobot index](https://huggingface.co/datasets/imbench/imbench-dataset) | Real Panda task datasets, including dynamics tasks such as linear/bounce intercept; current task cards expose small per-task episode sets | The released descriptions do not establish same-state, same-candidate, different-matched-history re-execution groups | Not admissible without stronger reset/pair provenance |

The BridgeDataV2 failure derivative found during the search was also excluded:
its failures are generated by offline trajectory perturbation rather than
physical re-execution, which reproduces the exact scientific problem already
identified in the public UR5 audit.

## Conclusion

No checked public source currently proves the paper's required matched physical
intervention. Some provide real successes and failures, and RRC exposes unusually
complete execution traces, but re-pairing nearby episodes after the fact would
weaken “same physical state and same candidate” into an unverifiable similarity
claim. The three-family, 36-pair preregistered collection therefore remains the only admitted
route unless a source owner supplies explicit reset and pair provenance.

This conclusion is about claim eligibility, not dataset quality. Each rejected
source remains useful for its stated benchmark purpose.
